# 2026-10-25 · 架构设计第一轮（整体方案）

参与者：项目负责人 + AI 助手（ZCode）。主题：整体架构。用户事先明确：跳过细节级 open questions，先定整体。

## 过程与纠偏记录

1. 助手最初给的需求分析带 12 个 open questions，用户反馈「太细节了，需要先讨论整体」。此后讨论一律从系统级抉择切入（此偏好已入记忆与工作方式）。
2. 模式选型：助手原倾向「逆命令为主 + 快照兜底」；用户定为 Command + Composite + Memento 三件套，并进一步提出函数式状态传递风格。两者合并为「状态时间线 + 游标」：执行 = 校验 → 克隆 → 在克隆上操作 → 追加状态；undo/redo = 移动游标。助手原方案被替换。
3. 容器变换表示：助手给出原文夹缝分析（L177/L178/L181/L217 与 §0 L56/L60），双方同意内部坐标扁平化，read 时展开 translate/scale、其他变体警告降级。
4. 模块划分：助手原草案六模块（含 render）；用户改为五模块（io/types/command/engine/cli）并追问 render 职责，最终 render 并入 command。依赖方向与校验链当场敲定。
5. XML 库：用户拍板不重复造轮子，定 @xmldom/xmldom（助手推荐，理由：DOM 保序；fast-xml-parser 对象映射会糊掉混合内容顺序）。
6. 用户分享个人项目中的 SDD 教训：spec 常耦合具体实现或代码库其他位置；spec 遗漏改动范围导致 agent 打临时适配补丁、破坏抽象层级。现行流程改为：先讨论必要实现细节 → 声明改动面与关键接口（人或 agent 按模块层级报）→ 实现。该流程已写入 `AGENTS.md` 工作循环第 3 步。
